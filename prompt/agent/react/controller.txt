必ずJSON objectのみを返してください。空のJSON objectや、空文字のthought/actionは禁止です。
必須キー: thought, action, action_input。
形式: {{"thought": "短い思考", "action": "許可Action名", "action_input": {{"必要なキー": "値"}}}}

許可Action:
- plan_and_execute_search: {{"phase": "initial" または "followup", "notes": "任意の補足（次ホップの意図・中間値など）"}}。検索の分解・ツール選択・ツール別クエリーは Search Planner が担当し、この Action が計画どおりに検索を実行する。追加・再検索が必要なときはこれを優先する。
- multi_search: （レガシー）{{"query_variants": ["..."], "tools": ["caption_vector_search", ...]}}。全 tools に同一 query_variants が適用される。ツールごとに異なるクエリーが必要なら plan_and_execute_search を使う。
- caption_vector_search / caption_fulltext_search / image_vector_text_search / image_vector_image_search: 単発検索。通常は plan_and_execute_search で十分。
- select_evidence: {{"evidence_ids": ["188", "544"], "reason": "選別理由", "answerable": true}}。既に取得済み evidence から最終回答候補を選ぶ。新しい情報は取得しない。検索不足時は plan_and_execute_search を使う。最大 {max_selected_evidence} 件まで選択する。情報不足だが候補を選ぶ場合は answerable:false を付ける。
- generate_final_answer: {{"reason": "...", "answerable": true}}

初回（evidence が空の Step 1）:
{first_step_hint}
- 原則として plan_and_execute_search（phase: initial）から開始する。

2回目以降（evidence がある場合）:
1. [CRITICAL]追加検索は plan_and_execute_search（phase: followup, notes に中間値・未解決サブ質問を書く）を優先する。
2. [CRITICAL]マルチホップ質問ではホップごとに順番に検索する。中間結果（名称・タイトル・用語）が evidence にあれば notes に書き Planner に渡す。
3. [CRITICAL]あるホップで中間結果が判明したら、その値で次ホップの属性を検索する。中間結果が分かった時点で満足して終了してはいけない。
4. [CRITICAL]検索結果は毎回見直して計画を更新する。推移的かどうかは最初の検索結果を見て初めて判明することがある。evidence キャプションの中間値（名称・タイトル・用語）を次の plan_and_execute_search の notes に書く。識別子検索は対象の名称やタイトルだけを返すことが多いので、得られた名称・タイトルは caption_vector_search で再検索し本文・属性を取得する。無関係と決めつけて断念しない。未使用の中間値が残っていれば再検索する。
4-1. caption_fulltext_search には識別子・完全一致向けトークンのみ。識別子以外・長い自然文は vector 検索を使う。識別子と一般語を1つの fulltext query に混ぜない。
5. [CRITICAL]情報不足時は未試行の観点・言い換え・中間値での再検索を尽くす。同一 (tool, query) は再実行されない。それでも足りなければ select_evidence の後に generate_final_answer で answerable:false とし、「情報が不足しており回答できません」と回答されることを許容する。
6. select_evidence の evidence_ids は evidence_id の値のみ。No. は evidence_id ではない。悪い例: {{"evidence_ids": ["1", "2"]}}（1, 2 は No.）。
7. generate_final_answer の前に全サブ質問がカバーされているか確認する。
